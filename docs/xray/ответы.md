# Анализ исходников XTLS/Xray-core (v26.7.28, commit `5ca6f4b`)

## Сводка: НЕ ПОДТВЕРЖДЕНО и расхождения с sing-box

Ниже перечислены критические архитектурные особенности, ограничения и отличия от sing-box, выявленные при анализе исходного кода:

1. **Отсутствие `ResetNetwork()`**: У Xray нет аналога `CommandServer.ResetNetwork()` из sing-box. Соединения и кэши не сбрасываются атомарно через публичный API.
2. **Глобальный синглтон менеджера Hysteria QUIC**: Менеджер клиентов `clientManager` в [`transport/internet/hysteria/dialer.go:317-356`](file:///E:/Projects/.tools/xray/transport/internet/hysteria/dialer.go#L317-L356) объявлен как глобальная переменная уровня пакета с `sync.Once`. При перезапуске инстанса ядра `Instance.Close()` старые сессии QUIC в мапе `manager.m` не очищаются принудительно, пока не отработает таймаут неактивности или ошибка сокета.
3. **Критические дыры в защите сокетов (`VpnService.protect` bypass)**:
   - **`utils.CheckRoutes()`**: В [`common/utils/probe_routes.go:12,16`](file:///E:/Projects/.tools/xray/common/utils/probe_routes.go#L12-L16) на Android (`isGUIPlatform == true`, [`common/utils/probe_routes.go:60-63`](file:///E:/Projects/.tools/xray/common/utils/probe_routes.go#L60-L63)) каждые 100 мс вызывается сырой `net.Dial("udp4", "192.33.4.12:53")` и `net.Dial("udp6", "[2001:500:2::c]:53")` в обход `internet.Controllers`. Это приводит к утечке сокетов и зацикливанию туннеля.
   - **DNS over QUIC (DoQ)**: В [`app/dns/nameserver_quic.go:266`](file:///E:/Projects/.tools/xray/app/dns/nameserver_quic.go#L266) вызывается `quic.DialAddr(...)`, который создает сырой UDP-сокет в обход `internet.DialSystem` и `internet.Controllers`.
4. **Конфигурация параметров Hysteria2 и Salamander**:
   - В sing-box параметры обфускации задаются внутри `obfs` в структуре аутбаунда. В Xray поля `obfs` нет — обфускация задается через универсальный транспортный стек `streamSettings.finalmask.udp` (`type: "salamander"`).
   - Поля `up`, `down`, `congestion`, `udphop` внутри `streamSettings.hysteriaSettings` полностью игнорируются ядром ([`infra/conf/transport_method.go:779-781`](file:///E:/Projects/.tools/xray/infra/conf/transport_method.go#L779-L781)). Реально читаются только поля `brutalUp`, `brutalDown`, `congestion`, `udpHop` внутри `streamSettings.finalmask.quicParams` ([`infra/conf/transport_finalmask.go:930-945`](file:///E:/Projects/.tools/xray/infra/conf/transport_finalmask.go#L930-L945)).
5. **Поведение при отсутствии файлов Geo-баз (`geoip.dat` / `geosite.dat`)**:
   - В sing-box гео-правила могут компилироваться в единый бинарный формат или пропускаться. В Xray при отсутствии файла или тега парсер возвращает ошибку во время сборки конфигурации ([`common/geodata/geodat_loader.go:16-25`](file:///E:/Projects/.tools/xray/common/geodata/geodat_loader.go#L16-L25), [`common/geodata/rule_parser.go:76,213`](file:///E:/Projects/.tools/xray/common/geodata/rule_parser.go#L76-L213)), из-за чего **отвергается весь конфиг целиком** и ядро не стартует.

- **TCP (RAW, SplitHTTP, WebSocket, gRPC)**: **Покрыт**. В [`transport/internet/hysteria/dialer.go:118,147`](file:///E:/Projects/.tools/xray/transport/internet/hysteria/dialer.go#L118-L147) базовый UDP-сокет и сокеты Udphop создаются через `internet.DialSystem`, оборачиваются в `PacketConnWrapper` и передаются в `quic.Transport`.
- **REALITY**: **Покрыт**. В Xray REALITY работает поверх RAW TCP, XHTTP и gRPC ([`infra/conf/transport_internet.go:100-101`](file:///E:/Projects/.tools/xray/infra/conf/transport_internet.go#L100-L101)), которые используют `internet.DialSystem`.

### Исчерпывающий список мест с обходом `RegisterDialerController` (УТЕЧКИ)

Каждое из следующих мест создает сетевое соединение в обход `internet.Controllers` и приведет к зацикливанию трафика на Android:

1. **`common/utils/probe_routes.go:12,16`** — **КРИТИЧЕСКАЯ УТЕЧКА**:
   ```go
   conn, err := net.Dial("udp4", "192.33.4.12:53")
   conn, err := net.Dial("udp6", "[2001:500:2::c]:53")
   ```
   *Контекст*: Вызывается из `CheckRoutes()` на Android (`isGUIPlatform == true`, строка 62) каждые 100 мс при любом DNS-запросе или проверке маршрута ([`app/dns/nameserver.go:170`](file:///E:/Projects/.tools/xray/app/dns/nameserver.go#L170), [`proxy/freedom/freedom.go:314`](file:///E:/Projects/.tools/xray/proxy/freedom/freedom.go#L314), [`app/dns/dns.go:224`](file:///E:/Projects/.tools/xray/app/dns/dns.go#L224)). 2. **`app/dns/nameserver_quic.go:266`** — **КРИТИЧЕСКАЯ УТЕЧКА при DoQ**:
   ```go
   conn, err := quic.DialAddr(context.Background(), s.destination.NetAddr(), ...)
   ```
   *Контекст*: DNS over QUIC (`quic://...`) создает сокет напрямую в библиотеке `quic-go` без использования `internet.DialSystem`.
3. **`features/dns/localdns/client.go:38`** — **ПОТЕНЦИАЛЬНАЯ УТЕЧКА**:
   ```go

   ```
   *Контекст*: Если `len(internet.Controllers) == 0` на момент создания `localdns.New()`, системный резолвер вызывает стандартный `net.LookupIP` без контроллера.
4. **`main/confloader/external/external.go:70`**:
   `var d net.Dialer; d.DialContext(...)` — загрузка внешнего конфига по URL.
5. **`app/router/webhook.go:69`**:

## Блок 4 — Смена сети (Wi-Fi → мобильная)

### Кэши и структуры, привязанные к старому интерфейсу
1. **Менеджер сессий Hysteria QUIC (`clientManager`)**: В [`transport/internet/hysteria/dialer.go:317-356`](file:///E:/Projects/.tools/xray/transport/internet/hysteria/dialer.go#L317-L356) структура `clientManager` хранит активные клиенты `*client` с их `*quic.Conn` и `pktConn`. Она глобальна и живет на уровне всего Go-процесса.
2. **Кэш DNS-ответов**: `app/dns/cache.go` (`CacheController`) кэширует IP-адреса по TTL. При переходе с Wi-Fi на LTE локальные/внутренние адреса могут стать невалидными.

## Блок 5 — Журнал и счётчики

### Перехват журнала ядра из Go (для Kotlin колбэка)
Для перехвата логов ядра необходимо реализовать интерфейс `log.Handler` ([`common/log/log.go:14-16`](file:///E:/Projects/.tools/xray/common/log/log.go#L14-L16)) и зарегистрировать его через `log.RegisterHandler(...)` ([`common/log/log.go:38`](file:///E:/Projects/.tools/xray/common/log/log.go#L38)).

```go
package corebridge

import (
	"github.com/xtls/xray-core/common/log"
)

type KotlinLogCallback func(level int32, message string)

type AppLogHandler struct {
	callback KotlinLogCallback
}

func (h *AppLogHandler) Handle(msg log.Message) {
	if h.callback == nil {
		return
	}
	switch m := msg.(type) {
	case *log.GeneralMessage:
		h.callback(int32(m.Severity), m.String())
	case *log.AccessMessage:
		h.callback(int32(log.Severity_Info), m.String())
	case *log.DNSLog:
		h.callback(int32(log.Severity_Info), m.String())
	default:
		h.callback(int32(log.Severity_Info), msg.String())
	}
}

func SetupLogger(cb KotlinLogCallback) {
	log.RegisterHandler(&AppLogHandler{callback: cb})
}
```

### Счётчики трафика (`app/stats`) внутри Go-процесса
Чтобы ядро вело учет байтов по исходящим, в JSON-конфиге должны быть включены политики статистики:

```json
{
  "stats": {},
  "policy": {
    "system": {
      "statsOutboundUplink": true,
      "statsOutboundDownlink": true
    }
  }
}
```

При этом аутбаунд-обработчики автоматически регистрируют счетчики с именами ([`app/proxyman/outbound/handler.go:35-56`](file:///E:/Projects/.tools/xray/app/proxyman/outbound/handler.go#L35-L56)):
- `outbound>>><TAG>>>>traffic>>>uplink`
- `outbound>>><TAG>>>>traffic>>>downlink`

Чтение счетчиков из Go:

```go
package corebridge

import (
	"github.com/xtls/xray-core/core"
	"github.com/xtls/xray-core/features/stats"
)

type OutboundTraffic struct {
	Uplink   int64
	Downlink int64
}

func GetOutboundTraffic(instance *core.Instance, tag string) OutboundTraffic {
	var res OutboundTraffic
	if instance == nil {
		return res
	}

	feat := instance.GetFeature(stats.ManagerType())
	if feat == nil {
		return res
	}
	manager, ok := feat.(stats.Manager)
	if !ok || manager == nil {
		return res
	}

	if up := manager.GetCounter("outbound>>>" + tag + ">>>traffic>>>uplink"); up != nil {
		res.Uplink = up.Value()
	}
	if down := manager.GetCounter("outbound>>>" + tag + ">>>traffic>>>downlink"); down != nil {
		res.Downlink = down.Value()
	}

	return res
}
```

### DNS (`infra/conf/dns.go`)

#### Форма списка серверов
Серверы в `dns.servers` могут быть строками (например, `"1.1.1.1"`, `"https://1.1.1.1/dns-query"`, `"quic://dns.adguard.com"`, `"localhost"`) либо объектами `NameServerConfig` ([`infra/conf/dns.go:19-35,38-82`](file:///E:/Projects/.tools/xray/infra/conf/dns.go#L19-L82)).

#### Привязка DNS-сервера к конкретному исходящему
В объекте `NameServerConfig` задается поле `"tag"` (например, `"tag": "dns-direct"`).
При отправке запроса ядро помечает его входящий контекст данным тегом ([`app/dns/nameserver.go:183`](file:///E:/Projects/.tools/xray/app/dns/nameserver.go#L183)):
```go
ctx = session.ContextWithInbound(ctx, &session.Inbound{Tag: c.tag})
```
В секции `routing.rules` запросы от этого DNS-сервера сопоставляются по правилу `inboundTag`:
```json
{
  "type": "field",
  "inboundTag": ["dns-direct"],
  "outboundTag": "direct"
}
```

#### Что делает `queryStrategy`
Определяет семейство запрашиваемых IP-адресов ([`infra/conf/dns.go:381-394`](file:///E:/Projects/.tools/xray/infra/conf/dns.go#L381-L394), [`app/dns/dns.go:54-82`](file:///E:/Projects/.tools/xray/app/dns/dns.go#L54-L82)):
- `"UseIP"` (`USE_IP`): запрашивает и возвращает как IPv4 (A), так и IPv6 (AAAA).
- `"UseIPv4"` / `"UseIP4"` (`USE_IP4`): отключает IPv6 и резолвит только IPv4 (A).
- `"UseIPv6"` / `"UseIP6"` (`USE_IP6`): отключает IPv4 и резолвит только IPv6 (AAAA).
- `"UseSys"` / `"UseSystem"` (`USE_SYS`): динамически проверяет поддержку IPv4/IPv6 на сетевых интерфейсах через `utils.CheckRoutes()` ([`app/dns/dns.go:61-67`](file:///E:/Projects/.tools/xray/app/dns/dns.go#L61-L67)).

#### Предотвращение утечек и зацикливания DNS
1. **Разделение Bootstrap DNS и проксируемого DNS**: Домен самого прокси-сервера (например, `node.example.com`) не должен резолвиться через тот же прокси-туннель. Для него настраивается статический адрес в `dns.hosts` или отдельный прямой сервер:
   ```json
   {
     "address": "1.1.1.1",
     "domains": ["node.example.com"],
     "tag": "dns-direct"
   }
   ```
2. **Маршрутизация по Inbound Tag**: Все DNS-запросы направляются через явные правила маршрутизации (`inboundTag: ["dns-direct"] -> outboundTag: "direct"`).
3. **Защита от внутреннего зацикливания**: В [`app/dns/dns.go:208`](file:///E:/Projects/.tools/xray/app/dns/dns.go#L208) ядро проверяет `if client.tag == inbound.Tag`, исключая рекурсивный опрос DNS-клиентом самого себя.
